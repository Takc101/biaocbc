# QQ 一键注册 · 部署指南

> 配套文件：`worker.js`（Cloudflare Worker）、`wrangler.toml`、`package.json`
> 网站侧改造已全部落在 `../index.html`，无需额外构建——本指南只讲如何把绑定服务部署上线。

---

## 0. 这套方案在做什么

```
用户浏览器                       Cloudflare Worker                QQ 开放平台
──────────                      ────────────────                ───────────
点「QQ 一键注册」   →  POST /api/bind/start   →   生成 6 位验证码（KV，10 分钟有效）
展示验证码 + 添加机器人入口     ← 返回 {code, shareUrl, botName}
                                    │
在 QQ 里 @机器人 发验证码  ──→  WebHook /qq/callback（ed25519 验签）
                                    │ 匹配验证码 → 记录 QQ openid
轮询 /api/bind/status      ←  返回 {status:"bound", openid}
                                    │
用 openid 注册/登录（写入 GitHub 上的 data.json）
```

**为什么不是标准 QQ OAuth？** QQ 开放平台没有面向「浏览器内网页」的 OAuth 流程（只有面向 App/小程序的接口），且其 API 不返回 CORS 头，而表白墙是纯静态站（GitHub Pages）没有服务端，标准 OAuth 在此架构下走不通。上面的「Worker 收 WebHook + 验证码绑定」是同等安全等级下唯一可落地的「一键」实现：用户全程只需在 QQ 里发一次验证码，之后同一 QQ 再次进入直接登录。

**安全边界：**
- 所有 QQ 事件都做 ed25519 签名校验，伪造事件无法完成绑定
- AppSecret 只存在于 Worker secrets，不出现在浏览器、data.json 或任何前端代码
- 验证码 6 位（约 8.8 亿组合）、10 分钟有效、一次性消费；待绑定码上限 500 个
- 机器人回复走被动消息（带 msg_id），不消耗 QQ 主动消息配额

## 2. 部署 Worker（约 5 分钟）

```bash
cd qq-bot
npm install          # 安装 wrangler
npx wrangler login   # 浏览器授权 Cloudflare
```

### 2.1 创建 KV 命名空间

```bash
npx wrangler kv namespace create QQ_BINDINGS
```

把输出的 `id` 填进 `wrangler.toml`：

```toml
[[kv_namespaces]]
binding = "QQ_BINDINGS"
id = "这里换成上面命令输出的 id"
```

### 2.2 注入敏感信息（secrets，不要写进文件）

```bash
npx wrangler secret put QQ_APP_ID       # 输入 1905821633
npx wrangler secret put QQ_APP_SECRET   # 输入 2qfUKA1skdWQKFA630ywvvvwxz148CHM
npx wrangler secret put SITE_ORIGIN     # 例：https://你的用户名.github.io
```

- `SITE_ORIGIN` 是 CORS 白名单，多个域名用英文逗号分隔；**本地调试（localhost）始终放行**，可留空
- AppSecret 曾在聊天记录里明文出现过，建议部署完成后到 QQ 开放平台**重置 Secret**，然后用新值重新 `wrangler secret put QQ_APP_SECRET`——旧值即作废

### 2.3 部署

```bash
npm run deploy       # 即 npx wrangler deploy
```

记下输出的地址，形如 `https://qq-bind-worker.<你的子域>.workers.dev`，后面两步都要用。

### 2.4 自检

```bash
curl https://qq-bind-worker.<你的子域>.workers.dev/api/health
```

返回 `{"ok":true,"configured":true,"botName":"…","shareUrl":"…"}` 说明 secrets、KV、QQ API 全链路通了。

## 3. 配置 QQ 开放平台（机器人后台）

打开 [QQ 开放平台机器人管理](https://q.qq.com) → 选择 AppID `1905821633` 的机器人：

1. **开发设置 → 回调地址**：填
   `https://qq-bind-worker.<你的子域>.workers.dev/qq/callback`
2. **事件订阅**：勾选
   - `GROUP_AT_MESSAGE_CREATE`（群聊里 @机器人）
   - `C2C_MESSAGE_CREATE`（单聊）
   - Token 留空即可（本方案不用这个字段）
3. **保存**。QQ 会立即发一次 `op=13` 校验请求，Worker 会自动完成 ed25519 应答——看到「验证成功」即回调地址生效。
4. **IP 白名单**（如页面要求）：填 Cloudflare Workers 的出网段不可行（动态 IP），保持关闭/不填即可；WebHook 模式没有这个强制项。

> **群机器人已入群待配置**：机器人已加入 QQ 群 `1097992253`，但**事件订阅必须在 QQ 开放平台后台勾选并保存**（上面的第 2 步）后才会收到群消息。没配之前，用户在群里 @机器人 是没有任何反应的——这是最常见的「机器人装了却不理我」的原因。
>
> 保存回调地址后，机器人进入群/被添加的方式不变（用机器人分享链接）。网站上的「添加机器人」按钮会自动带上 Worker 从 `/users/@me` 获取的 `share_url`，无需手动填。

---

## 4. 网站后台打开开关

1. 用管理员账号登录表白墙 → 「我的」→ 管理后台 → **设置** tab
2. 找到「QQ 一键注册」卡片：
   - **绑定服务地址**：填 Worker 域名（`https://qq-bind-worker.<你的子域>.workers.dev`，不要带结尾斜杠）
   - **机器人添加链接**：留空即自动获取；只有在自动获取失败时才手动填
   - 先点 **测试连接**，状态显示连通后，勾选开关、点 **保存 QQ 设置**
3. 保存后回到登录弹窗，应出现「QQ 一键注册」按钮

开关和地址都存在 GitHub 上的 `data.json`（`qqBot.enabled / qqBot.workerUrl`），关掉开关入口立即隐藏，已注册的 QQ 用户不受影响。

## 5. 用户侧实际体验

1. 登录弹窗点「QQ 一键注册」
2. 页面显示 6 位验证码 + 「添加机器人」入口，10 分钟倒计时
3. 用户在 QQ 里 @机器人 把验证码发过去（或私聊机器人）
4. 机器人回复「✅ 绑定成功」——**同时网页自动检测到，完成注册并登录**
5. **昵称**：群聊场景下 Worker 会透传 QQ 昵称（事件里的 `author.username`），新用户直接用它；单聊场景 QQ 不返回昵称，退化为「QQ用户####」占位名，可在「我的」页面修改。老用户若还是占位名，下次登录会自动补上 QQ 昵称（用户改过名字则不动）
6. **头像**：QQ 平台在群/单聊机器人场景**不提供用户头像**（隐私边界，官方文档无此字段），所以默认头像是昵称首字的彩色圆形——注册后可在「我的」页点击头像上传自己的图片

> 搜索和主页也按这套身份走：全屏搜索页（点首页搜索框进入）可以搜投稿和用户，点头像进对方主页看 TA 的投稿网格；「动态」只有本人能在自己主页看到。

第二次同一 QQ 进入：重复步骤 1–4，直接登录老账号，不重复注册。

## 7. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `/api/health` 返回 `configured:false` | secrets 没打全：`wrangler secret list` 检查，缺哪个补哪个 |
| health 通但 `botName` 为空 | QQ API 取机器人信息失败：确认 AppID/Secret 正确、机器人未被封禁；`wrangler tail` 看具体报错 |
| QQ 后台保存回调地址报错 | 地址少写了 `/qq/callback`；或 Worker 没部署成功 |
| 用户在 QQ 发了验证码，网页无反应 | ① 确认事件订阅勾了 `GROUP_AT_MESSAGE_CREATE`/`C2C_MESSAGE_CREATE`；② `wrangler tail` 看有没有收到事件；③ 超过 10 分钟码已过期，重新获取 |
| 机器人没回复 | 被动回复受「同一 msg_id 5 分钟内最多 5 条」限制，属正常上限；`wrangler tail` 看「发送群消息失败」日志 |
| 后台「测试连接」失败 | 地址填错（常见：带了结尾 `/`、或用了自定义域名但没配 DNS）；SITE_ORIGIN 不含网站域名时浏览器 CORS 也会拦 |
| 想临时关闭功能 | 后台设置里关开关即可，无需动 Worker |

## 8. 配额与成本（免费额度内）

| 资源 | 免费额度 | 本方案用量（每次注册） |
|---|---|---|
| Workers 请求 | 10 万次/天 | 1 次 start + 约 1–300 次轮询 + 1 次回调 |
| KV 读 | 10 万次/天 | 同上 |
| KV 写 | 1000 次/天 | 2–3 次（建码、绑定、回写 replied） |

轮询间隔是 2 秒（`index.html` 中 `QQBind.tick` 的 `2000` 毫秒）。若日注册量预计超过 300 人，把该值调大（如 5000）即可把 KV 读控制在额度内；除此之外零费用。
